1. Branch Structure & Roles

Our repository uses a 3-tier structure to protect production and prevent code conflicts:

Branch Purpose Who Works Here? Direct Push?
main Production release & Hackathon final demo. Team Lead Only NEVER
dev Integration & Staging branch. All finished work merges here first. Entire Team Merge / PR only
fullstack/Lucas Lucas's dedicated feature & development branch. Lucas YES (Your branch)
fullstack/Rory Rory's dedicated feature & development branch. Rory YES (Your branch)
fullstack/Dokotela Dokotela's dedicated feature & development branch. Dokotela YES (Your branch)

2. First-Time Setup (Onboarding)

Run these commands once when you first set up the project on your laptop:

# 1. Clone the repository
git clone https://github.com/BohaniLucas/AssetBridge.git
cd AssetBridge

# 2. Fetch all branches created on GitHub
git fetch origin

# 3. Switch to your personal branch (choose your name):
# For Rory:
git checkout fullstack/Rory

# For Dokotela:
git checkout fullstack/Dokotela

# For Lucas:
git checkout fullstack/Lucas

# 4. Confirm you are on your branch (look for the asterisk *)
git branch

3. Daily Morning Routine: Syncing with dev (dev → your branch)

Crucial Habit: Before you write any new code each morning, always pull the newest updates that teammates merged into dev so your branch never falls behind!

# Step 1: Switch to dev and get the latest changes from teammates
git checkout dev
git pull origin dev

# Step 2: Switch back to your own branch
git checkout fullstack/<your-name>

# Step 3: Merge the new dev updates into your branch
git merge dev

# Now you are 100% up-to-date and ready to code!

4. Writing Code & Committing Cleanly

Work exclusively in your personal branch (fullstack/<your-name>):

# 1. Check what files you have modified
git status

# 2. Stage your modified files
git add .

# 3. Commit with a meaningful message explaining what you built
git commit -m "feat(invest): added USDT token offering unit pricing"

# 4. Push your work to your personal branch on GitHub
git push origin fullstack/<your-name>

5. Pushing Your Finished Work to dev (your branch → dev)

When you finish a feature, test it locally first. Then merge it into dev using either method:

Method A: GitHub Pull Request (Recommended & Safest)

  1. Push your branch: git push origin fullstack/<your-name>
  2. Go to GitHub: https://github.com/BohaniLucas/AssetBridge
  3. You will see a yellow banner: "fullstack/<name> had recent pushes. Compare & pull request".
  4. Click Compare & pull request.
  5. CRITICAL: Ensure base: dev ← compare: fullstack/<your-name>. (Do NOT merge into main!).
  6. Click Create pull request → then click Merge pull request → Confirm merge.

Method B: Direct Terminal Merge (Fast)

# 1. Make sure your own branch is committed and pushed
git push origin fullstack/<your-name>

# 2. Switch to dev and make sure dev is up to date
git checkout dev
git pull origin dev

# 3. Merge your branch into dev
git merge fullstack/<your-name>

# 4. Push updated dev to GitHub
git push origin dev

# 5. Switch back to your own branch for your next task
git checkout fullstack/<your-name>

6. How to Resolve Merge Conflicts (No-Panic Guide)

A merge conflict happens when you and a teammate edited the exact same line in the same file. Git pauses and asks you which version to keep.

  1. Open the project in VS Code. Conflicting files will appear in purple with an exclamation mark.
  2. Click on the file. Above the conflicting section, VS Code gives you 3 clickable buttons:
    • Accept Current Change: Keeps your code.
    • Accept Incoming Change: Keeps your teammate's code.
    • Accept Both Changes: Keeps both.
  3. Choose the right button (or manually edit the code to combine both).
  4. Save the file.
  5. In terminal, finalize the merge: 
    git add .
git commit -m "fix: resolved merge conflict with dev"
git push origin fullstack/<your-name>

7. Team Golden Rules

  • Rule 1: NEVER push directly to main. All code must go through dev first.
  • Rule 2: NEVER commit .env or private keys. They are git-ignored.
  • Rule 3: Sync with dev daily. The more frequently you pull from dev, the less likely you will ever encounter conflicts.
  • Rule 4: Test before pushing to dev. Run npm test to verify tests pass.
